# 游戏评论洞察 Agent（Game Review Insight Agent）

> 输入一堆玩家评论，自动产出「情感 + 议题 + 群体差异」的结构化洞察，把散乱的舆情变成可决策的数据。

以《明日方舟：终末地》TapTap 评论为首个落地场景，架构与游戏解耦——换一个 `config/games/*.yaml` 即可分析原神等任意游戏。

---

## 一、产品定位

**一句话**：面向游戏运营/策划的**评论洞察工具**，把「几万条自然语言评论」压缩成「几张能直接进周报的图表和显著性结论」。

**它不是**：通用情感 API（那些只给正负分，不懂游戏语境）。
**它是**：内置游戏领域知识（抽卡、保底、基建、鹰角/米哈游等黑话）、能区分「抱怨 vs 建议」、能做群体间显著性检验的**垂直分析 Agent**。

---

## 二、用户价值

| 目标用户 | 痛点 | 本工具提供的价值 |
|---|---|---|
| **运营 / 舆情** | 人工翻几千条评论，凭感觉写"口碑回暖" | 自动量化：负面率从 62%→46%，且 **p<0.001 统计显著** |
| **策划 / 制作人** | 不知道玩家骂的到底是哪块、该先修什么 | 按 6 大议题拆分负面率并按**效应量排序**，直接指出优先级 |
| **数据分析师** | 情感/议题标注成本高、口径不统一 | 提示词工程 + LLM 一次性标注，附 eval 集与准确率追踪 |

**核心差异化**：分类只是中间产物，**"哪个议题回暖最多、哪个仍是短板"这种带统计置信度的结论**才是交付物。

---

## 三、功能规划（当前已实现）

- **情感分类**：positive / negative / neutral 三分类，专门处理反讽、长篇吐槽结尾反转、建议体差评等易错场景（见 `prompts/sentiment.yaml`）
- **议题分类**：将评论判入玩法 / 商业化 / 技术 / 角色 / 运营 / 其他 6 类，支持多标签 + 主议题（见 `prompts/topics.yaml`）
- **配置化多游戏**：游戏专属内容（名称、议题定义、版本表）全部外置到 `config/games/*.yaml`，代码零改动切换游戏
- **批量流水线**：断点续跑 + 增量落盘 + 错误日志（`run_batch_*.py`）
- **群体差异检验**：卡方 + Cramer's V 效应量 + 期望频数校验，判断两版本/群体差异是否显著（`eval/aggregators.py`）
- **质量评估闭环**：人工标注 eval 集 + 准确率验证脚本 + 提示词迭代记录（`eval/`）

## 四、快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 配置 API Key（DeepSeek）：复制模板后填入你的 key（请存为 UTF-8）
cp .env.example .env

# 3. 单条体验
python -c "from agent import classify, LLMClient; print(classify('美术顶但抽卡太坑，总体还行', LLMClient()))"

# 4. 批量跑（可先在脚本里设 MAX_ROWS=20 试跑）
python run_batch_sentiment.py
python run_batch_topics.py

# 5. 看完整分析演示
jupyter notebook notebooks/demo.ipynb
```

> 只想看结果不想花钱调用？`notebooks/demo.ipynb` 内置了预跑结果（`agent_full_results.csv`），**无需 API Key 即可从头跑到出图**。
>
> ⚠️ `data/` 下的原始玩家评论**未随仓库发布**（隐私考量）。demo 与聚合分析只依赖已随仓库提供的 `agent_full_results.csv`，不受影响；但第 4 步的批量脚本需自备原始数据。

## 七、成本估算（粗略量级）

以 DeepSeek `deepseek-chat` 为例，单条评论走**两次**调用（情感 + 议题）：

- 输入：system prompt（约 1.3k tokens）+ 评论正文（截断 500 字），输出约几十 tokens
- **单条约 ¥0.005–0.01；全量 2000+ 条约 ¥10–20**（按现价，量级供参考）
- 优化点：system prompt 每次调用完全相同，开启 **prompt 缓存**后输入成本可再降一个量级

> 具体金额随官方定价浮动，正式核算请以 DeepSeek 官网现价为准。

## 八、已知局限

- **议题是"分类"而非"聚类"**：判入 6 个**预定义**类别，无法发现新兴议题（v1.3 计划补无监督聚类）
- **数据来源单一**：当前仅 TapTap（安卓），不含 iOS/PC 群体，跨平台对比暂不可做
- **版本对比存在幸存者偏差**：不同时期是不同评论者，负面率下降部分来自"不满玩家已流失"，结论措辞需谨慎
- **LLM 分类非 100% 准确**：以 eval 集准确率为准，关键结论建议抽样复核
